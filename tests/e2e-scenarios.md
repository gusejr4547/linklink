# E2E 테스트 시나리오 — Task 14 (핵심 기능 통합 테스트)

Playwright MCP로 검증할 시나리오 목록. `test-verifier` 서브에이전트가 이 문서를 기준으로 실행하고 결과를 기록한다.

## 1. 전체 사용자 여정

1. 랜딩 페이지 접속
2. 회원가입 (신규 계정, 이메일 인증 불필요)
3. 로그인 → `/links` 리다이렉트 확인
4. 빈 상태 UI 확인
5. 링크 저장 (메타데이터 자동 수집 성공 케이스)
6. 링크 저장 (메타데이터 수집 실패 → 수동 입력 폴백 케이스)
7. 태그·메모 입력 후 저장
8. 읽음/즐겨찾기 토글 → 새로고침 후 상태 유지 확인
9. 검색어 입력 → 결과 필터링 확인
10. 태그/읽음상태/즐겨찾기 조합 필터 확인
11. 링크 삭제 → 목록에서 사라짐 확인
12. 로그아웃 → 랜딩 또는 로그인 페이지로 이동 확인

## 2. 엣지 케이스

- 300자 이상 제목 → 카드에서 truncate 처리 확인
- 1000자 이상 URL 저장 시도
- 태그 0개 링크 → 배지 영역 비어있음
- 메모 미입력 → 메모 영역 미표시
- 검색어에 유니코드/이모지("🔥") 입력 → 정상 동작
- 썸네일 404/깨진 이미지 → placeholder 또는 숨김 처리
- 잘못된 이미지 URL

## 3. 에러 시나리오

- 메타데이터 수집 타임아웃 → 수동 입력 폼 전환
- 잘못된 URL 형식(프로토콜 없음 등) → 인라인 에러 메시지
- Server Action 실패 시 토스트 에러 표시
- 동시 업데이트: 2개 탭에서 같은 링크 토글

## 4. 보안

- 비로그인 상태에서 `/links` 직접 접근 → `/auth/login` 리다이렉트
- 다른 사용자 계정으로 로그인 시 타 사용자 링크 미노출 (RLS 검증)
- 검색어에 XSS 스크립트(`<script>alert(1)</script>`) 입력 → 스크립트 미실행, 이스케이프 확인
- 검색어에 SQL 인젝션 패턴(`' OR '1'='1`) 입력 → 오류 없이 정상 처리

## 5. 성능

- 링크 목록 로딩 시간 (가능한 범위 내 확인)
- 검색 디바운스(약 500ms) 동작 확인

## 6. 접근성

- Tab 키로 모든 인터랙션 요소(저장 버튼, 카드 내 토글/삭제, 검색 입력, 필터) 접근 가능
- 모달에서 Esc 키로 닫기
- 토글/삭제 버튼에 `aria-label` 존재 확인

## 결과 기록

발견된 결함은 해당 원인 Task(9~13)의 서브태스크에 회귀 항목으로 `update_subtask`를 통해 기록한다.
