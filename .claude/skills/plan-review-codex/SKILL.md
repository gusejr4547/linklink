# Plan Review with Codex (GPT)

Claude Code의 Plan Mode가 만든 계획을, 로컬에 설치된 **codex CLI**를 통해 GPT로 다시 검토받는다.

- **인증**: codex CLI는 API 키가 아니라 **ChatGPT 구독 계정(OAuth 로그인)** 을 사용하므로 `OPENAI_API_KEY` 같은 환경변수 설정이 필요 없다 — `~/.codex/config.toml`에 이미 인증 정보가 저장되어 있고, `codex login status`가 "Logged in using ChatGPT"를 반환하면 준비된 것이다.
- **컨텍스트 이전(export)**: Claude Code의 plan을 codex로 "옮기는" 작업은 셸 환경변수나 별도 import 명령으로 하는 게 아니다 — `codex exec --help`에 그런 옵션 자체가 없다 (`-i`는 이미지 첨부용, `--add-dir`는 쓰기 권한 추가용일 뿐, 텍스트 컨텍스트를 넘기는 플래그는 없다). 대신 **3~4단계에서처럼 plan 원문 전체를 프롬프트 파일에 그대로 담아 `codex exec`의 stdin으로 넘기는 것**이 사실상 유일하고 정확한 "export" 방법이다. 실측 테스트에서 이 방식으로 넘긴 plan 속 세부사항(함수명, 커밋 해시 등)을 GPT가 정확히 참조해 답변하는 것을 확인했다.

같은 모델(Claude)이 자기 계획을 스스로 재검토하면 같은 사각지대를 반복해서 놓치기 쉽다. 이 스킬의 목적은 아키텍처가 다른 모델(GPT)에게 "진짜 남"의 시선으로 계획을 비판적으로 보게 하는 것이다. 그래서 프롬프트는 단순히 "괜찮은지 봐줘"가 아니라, 구체적으로 무엇을 놓치기 쉬운지(엣지케이스, 과설계, 잘못된 가정, 숨은 리스크)를 짚어 요청한다.

## 실행 절차

### 1. 검토 대상 계획 찾기

- 사용자가 파일 경로나 계획 텍스트를 직접 줬다면 그것을 사용한다.
- 그렇지 않고 "방금 짠 계획", "이 plan" 같이 지칭만 했다면, Bash 툴로 실제 수정 시각 기준 최신 파일을 찾는다:
  ```bash
  ls -t ~/.claude/plans/*.md | head -1
  ```
  **`Glob` 툴은 쓰지 말 것** — `~/.claude/plans/`처럼 파일이 많이 쌓인 평평한 디렉터리에서 "수정시각 최신순 정렬"이 실제 mtime과 어긋나는 것이 확인됐다 (예: 실제 최신 파일이 Aug 28인데 Glob은 Jul 29 파일을 1순위로 반환). `ls -t`(또는 PowerShell이면 `Get-ChildItem ~\.claude\plans\*.md | Sort-Object LastWriteTime -Descending | Select-Object -First 1`)로 직접 정렬해야 한다.
  - 대화 중에 이미 plan 내용이 있다면 굳이 파일을 다시 읽지 않고 그 내용을 써도 된다.
- 여러 후보가 애매하면 파일명과 수정 시각을 사용자에게 보여주고 확인받는다.

### 2. 코드까지 확인시킬지 결정

기본은 **계획 텍스트만** 전달하는 "빠른 모드"다. 다음 중 하나에 해당하면 **코드 인지 모드**로 전환한다 (사용자가 "코드까지 확인해서", "실제로 그 함수/파일이 있는지 보고" 등을 언급하거나, 계획이 기존 코드 구조에 대한 구체적 가정을 다수 포함해 사실 확인이 중요해 보일 때):

- 빠른 모드: `--skip-git-repo-check -C <스크래치패드 디렉터리>` 로 실행 — codex가 실제 저장소를 건드릴 이유가 없는 격리된 디렉터리에서 순수 텍스트만 검토.
- 코드 인지 모드: `-C <저장소 루트>` 로 실행 (`--skip-git-repo-check` 생략) — codex가 `sandbox read-only`로 저장소 파일을 직접 열람하며 계획의 사실 관계를 검증. 더 정확하지만 느리고 codex 사용량이 늘어나므로, 필요할 때만 쓴다.

어느 모드든 **`-s read-only`는 항상 사용한다** — 리뷰는 분석 작업이지 코드 실행/수정 작업이 아니므로, 실수로라도 codex가 파일을 쓰거나 명령을 실행하지 못하게 막는다.

> **참고**: `-C`로 작업 디렉터리를 스크래치패드로 지정해도(`--skip-git-repo-check`), `-s read-only` 샌드박스는 쓰기/네트워크만 제한할 뿐 파일 시스템 읽기 자체는 다른 디렉터리까지 막지 않는 것으로 실측됐다 — 실제로 "빠른 모드"로 실행했는데도 GPT가 저장소의 git 커밋 이력과 작업 트리 상태를 파악한 사례가 있었다. 즉 "빠른 모드"는 codex가 저장소를 적극적으로 탐색하지 않도록 유도하는 정도이지, 강제 격리를 보장하지는 않는다. 민감한 정보 격리가 중요한 상황이 아니라면 문제 없지만, 이 차이를 사용자에게 사실과 다르게 설명하지 않는다.

### 3. 리뷰 프롬프트 작성 (plan을 codex 컨텍스트로 export하는 단계)

계획 원문 전체를 포함하고, 아래와 같은 요청을 덧붙인 프롬프트를 임시 파일로 작성한다 (긴 계획 텍스트를 셸 인자로 직접 넘기면 따옴표/이스케이프 문제가 생기므로 반드시 파일 → stdin으로 전달한다). codex에는 Claude Code plan을 가져오는 전용 import 기능이 없으므로, plan 원문을 프롬프트에 통째로 삽입해 stdin으로 흘려보내는 것 자체가 곧 "컨텍스트 export"다:

```
다음은 Claude Code의 Plan Mode가 작성한 구현 계획입니다. 이 계획을 실행하기 전에
비판적으로 검토해주세요.

- 놓치기 쉬운 엣지케이스나 잘못된 가정이 있는지
- 불필요하게 과설계되었거나 반대로 너무 단순화된 부분이 있는지
- 계획에 언급된 기존 코드/구조에 대한 전제가 실제로 맞을 가능성이 있는지
- 실행 순서나 검증 방법에 빠진 단계가 있는지
- 구체적으로 개선하면 좋을 지점 (있다면 대안 제시)

문제가 없다고 판단되면 억지로 트집 잡지 말고 그렇게 말해주세요.
한국어로, 핵심만 간결하게 bullet로 답해주세요.

--- 계획 원문 ---
<여기에 계획 전문 삽입>
```

### 4. codex exec 호출

Bash 툴에서 실행한다 (Windows Git Bash 기준, `<` stdin 리다이렉션 사용):

```bash
codex exec -s read-only --skip-git-repo-check \
  -C "<스크래치패드 디렉터리>" \
  -o "<리뷰 출력 파일 경로>" \
  - < "<프롬프트 파일 경로>"
```

코드 인지 모드일 때는 `--skip-git-repo-check`를 빼고 `-C`를 저장소 루트로 바꾼다:

```bash
codex exec -s read-only \
  -C "<저장소 루트>" \
  -o "<리뷰 출력 파일 경로>" \
  - < "<프롬프트 파일 경로>"
```

- `-o`는 codex의 최종 답변만 깨끗하게 파일로 저장한다 (진행 로그·토큰 사용량 등 나머지 출력과 섞이지 않는다). 이 파일을 읽어서 다음 단계에 쓴다.
- `-s read-only`가 켜져 있으면 승인(approval) 프롬프트 없이 자동으로 "never"로 동작하므로, `-a`/`--ask-for-approval` 플래그는 `exec` 서브커맨드에 없다 — 붙이면 `unexpected argument` 에러가 난다.
- 실행 중 `failed to load models cache` 같은 WARN/ERROR 로그가 stderr에 섞여 나올 수 있는데, 이는 non-fatal이며 최종 답변 생성에는 영향 없다. `-o` 파일에 답이 정상적으로 들어있는지로 성공 여부를 판단한다.

### 5. 결과 정리 및 전달

1. `-o`로 지정한 파일을 읽는다.
2. GPT 리뷰 원문을 계획 파일 옆에 저장한다 (예: 계획 파일이 `~/.claude/plans/foo.md`라면 `~/.claude/plans/foo-gpt-review.md`로 복사). 나중에 다시 참고할 수 있게 하기 위함이다.
3. 채팅에는 리뷰 전문을 그대로 붙여넣지 말고, 핵심 지적 사항을 간결하게 요약해서 보여준다 — 특히 "문제없음"인지 "이 부분이 걱정됨"인지를 먼저 한 줄로 말하고, 근거가 되는 세부 지적을 이어서 정리한다.
4. GPT가 구체적인 개선 제안을 했다면, 계획을 그에 맞춰 수정할지 사용자에게 물어본다 (자동으로 계획 파일을 고치지 않는다 — 사용자 승인 후 반영).

## 주의사항

- `codex exec`는 비대화형이라 프롬프트가 비어 있거나 stdin이 없으면 그대로 멈출 수 있다 — 항상 프롬프트 파일을 `<`로 붙여준다.
- codex는 월 구독제이지 종량제 API가 아니지만, 무제한은 아니다. 같은 계획을 여러 번 반복 요청하지 말고, 계획이 크게 바뀐 뒤에만 다시 검토를 요청한다.
- 이 스킬은 **명시적으로 요청받았을 때만** 사용한다 — Plan Mode를 쓸 때마다, 또는 ExitPlanMode 직후마다 자동으로 실행하지 않는다.
