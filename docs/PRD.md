# LinkLink PRD (MVP)

## 1. 핵심 정보

- **목적**: 여기저기 흩어져 쌓이기만 하는 링크(유튜브, 깃허브, 블로그, SNS 등)를 한곳에 저장하고, 태그·메모·읽음 상태로 다시 찾을 수 있게 한다.
- **타깃 사용자**: 유용해 보이는 링크를 습관적으로 북마크/메모앱에 던져두지만, 나중에 "그거 어디 있었지" 하며 못 찾아서 결국 다시 안 보게 되는 1인 사용자.
- **왜 지금**: 저장은 쉽지만 "다시 찾기"가 안 되는 문제는 태그+검색만으로도 검증 가능한 수준이라, 소규모로 빠르게 만들어 직접 써보며 검증할 수 있다.

## 2. 사용자 여정

```
1. [랜딩 페이지]
   ↓ [회원가입 버튼]
2. [회원가입 페이지] (F000)
   ↓ [가입 완료, 이메일 인증]
3. [로그인 페이지] (F000)
   ↓ [로그인 성공]
   [조건: 실패] → 에러 메시지 → 3번
4. [링크 목록 페이지] (첫 진입 시 빈 상태 안내)
   ↓ [링크 저장 버튼 클릭]
5. [링크 저장 모달] URL 붙여넣기 → 메타데이터 자동 수집 미리보기 → 태그/메모 입력
   ↓ [저장]
   [조건: URL 형식 오류/수집 실패] → 에러 안내, 수동으로 제목만 입력하고 저장 가능 → 5번
6. [링크 목록 페이지] 새 카드 노출
   ↓ [검색어 입력 / 태그·읽음상태·즐겨찾기 필터 선택]
   [조건: 카드 클릭] → 새 탭에서 원본 링크 열림 → 사용자가 직접 읽음 토글 → 7번
   [조건: 즐겨찾기 토글] → 카드 상태 갱신 → 7번
7. [완료: 원하던 링크를 다시 찾아 확인함] → [링크 계속 저장] 또는 [세션 종료]
```

## 3. 기능 명세

| ID | 기능명 | 설명 | MVP 포함 이유 | 위치 |
|---|---|---|---|---|
| F000 | 인증(로그인/회원가입/로그아웃) | 이메일 기반 회원가입, 로그인, 로그아웃. Supabase Auth로 이미 구현 완료 | 개인별 링크 데이터 분리를 위한 최소 조건. 기존 스타터 템플릿에 구현되어 있어 재작업 불필요 | 페이지(로그인, 회원가입) / 컴포넌트(헤더 로그아웃 버튼) |
| F001 | 링크 저장/삭제 | URL을 붙여넣어 저장하고, 목록에서 개별 삭제 | 서비스의 핵심 진입 행위. 이게 없으면 아무것도 시작 안 됨 | 인터랙션(링크 목록 페이지의 저장 모달), 인터랙션(카드 삭제 버튼) |
| F002 | 메타데이터 자동 수집 | 저장 시 URL의 OG 태그(제목/설명/썸네일)를 서버에서 fetch해 자동 채움. 수집 실패 시 제목만 수동 입력 가능 | 제목 없이 URL만 쌓이면 "무슨 링크인지" 못 알아봐서 재검색이 무의미해짐 | 인터랙션(링크 저장 모달 내 미리보기) |
| F003 | 태그 | 링크 저장 시 자유 텍스트 태그를 추가하고, 목록에서 태그로 분류·필터링 | 사용자가 요청한 "내용별 분류"를 태그 하나로 통합해 기능 수를 늘리지 않으면서 해결 | 인터랙션(저장 모달 입력), 컴포넌트(목록 필터바) |
| F004 | 메모 | 저장 시 "왜 저장했는지" 짧은 메모 입력 | 나중에 검색으로 찾을 때 제목보다 메모가 기억을 더 잘 되살림 | 인터랙션(저장 모달 입력) |
| F005 | 읽음/안읽음 토글 | 카드에서 버튼 클릭으로 읽음 상태 전환 | 다 읽었는지 한눈에 구분해야 "쌓아두고 안 본다"는 원래 문제를 해결했다고 볼 수 있음 | 인터랙션(카드 내 버튼) |
| F006 | 즐겨찾기 토글 | 카드에서 버튼 클릭으로 즐겨찾기 전환, 필터로 즐겨찾기만 보기 | 자주 다시 볼 링크를 검색 없이 바로 접근하게 함 | 인터랙션(카드 내 버튼), 컴포넌트(목록 필터바) |
| F007 | 검색 및 필터 | 제목/메모/태그 텍스트 검색 + 태그/읽음상태/즐겨찾기 조합 필터 | "예전에 본 것 같은데 못 찾는" 원래 문제를 직접 해결하는 핵심 기능 | 컴포넌트(링크 목록 페이지 상단 검색·필터바) |

### MVP 이후 (제외)

| 기능 | 제외 이유 |
|---|---|
| 키워드 자동 추출/AI 분석 | 아이디어 원문에서도 "고급기능"으로 명시됨. 태그 수동 입력만으로 분류 문제를 우선 검증 가능 |
| 리마인드 알림(주기적으로 안 읽은 링크 알림) | 이메일 발송 인프라(Supabase Edge Function + cron/이메일 서비스 연동)와 발송 주기·구독 설정 UI가 추가로 필요해 복잡도가 큼. 핵심 가치("찾기")는 알림 없이 검색/필터만으로 검증 가능하며, 사용자가 직접 목록을 열어보는 습관으로 대체 가능(수동 대체) |
| 카테고리(별도 트리형 분류 체계) | 태그(F003)로 동일 문제를 더 단순하게 해결. 폴더/트리 구조는 관리 UI가 추가로 필요해 1인 개발 범위 초과 |
| 소셜 로그인, 비밀번호 재설정 UI 확장 | 이메일 인증만으로 개인 사용에 충분. 기존 스타터의 비밀번호 재설정 플로우는 유지하되 신규 개발 대상 아님 |
| 링크 자동 읽음 처리(클릭 시 자동 전환) | 오탐(실수 클릭) 가능성이 있어 수동 토글이 더 명확함. 자동화 없이도 문제 없음 |
| 다국어, 다크모드 커스터마이징 | 1인 사용에는 불필요. 다크모드는 스타터 템플릿의 ThemeSwitcher로 이미 충분 |
| 링크 공유/협업 | 타깃이 개인 사용자 한 명이라 공유 기능은 범위 밖 |

## 4. 메뉴 구조

```
비로그인 메뉴
├── 로그인 — F000
└── 회원가입 — F000

로그인 후 메뉴

└── 로그아웃 — F000
```

## 5. 화면별 상세

### 랜딩 페이지
- **역할**: 서비스 소개 및 로그인/회원가입 진입점
- **진입 조건**: 비로그인 상태에서 최초 접속
- **사용자 행동**: 로그인 또는 회원가입 버튼 클릭
- **주요 기능**: 없음(안내용 정적 화면)
- **다음 이동**: 로그인 페이지 또는 회원가입 페이지
- **포함 요소**: 없음

### 로그인 페이지
- **역할**: 이메일/비밀번호로 로그인
- **진입 조건**: 랜딩 페이지의 로그인 메뉴, 또는 회원가입 완료 후 이동
- **사용자 행동**: 이메일·비밀번호 입력 후 제출
- **주요 기능**: F000
- **다음 이동**: 성공 시 링크 목록 페이지 / 실패 시 에러 메시지 표시 후 동일 화면 유지
- **포함 요소**: 없음

### 회원가입 페이지
- **역할**: 이메일/비밀번호로 신규 계정 생성
- **진입 조건**: 랜딩 페이지의 회원가입 메뉴
- **사용자 행동**: 이메일·비밀번호 입력 후 제출
- **주요 기능**: F000
- **다음 이동**: 성공 시 이메일 인증 안내 → 인증 후 로그인 페이지 / 실패 시 에러 메시지
- **포함 요소**: 없음

### 링크 목록 페이지 (홈)
- **역할**: 저장한 모든 링크를 확인, 검색, 필터링, 관리하는 메인 화면
- **진입 조건**: 로그인 성공 후 자동 진입, 또는 로그인 후 메뉴의 "링크 목록"
- **사용자 행동**: 링크 저장, 카드 클릭(원본 링크 열람), 읽음/즐겨찾기 토글, 삭제, 검색어 입력, 필터 선택
- **주요 기능**: F001, F002, F003, F004, F005, F006, F007
- **다음 이동**: 카드 클릭 시 새 탭에서 원본 URL로 이동(페이지 자체는 유지) / 링크 0개 상태에서는 빈 상태 안내와 저장 버튼만 노출
- **포함 요소**:
  - 컴포넌트: 헤더(로그아웃), 검색·필터바(F007), 링크 카드 목록
  - 인터랙션: 링크 저장 모달(F001, F002, F003, F004), 카드 내 읽음 토글(F005)·즐겨찾기 토글(F006)·삭제 버튼(F001)

## 6. 데이터 모델

### links

| 필드명 | 설명 | 타입/관계 |
|---|---|---|
| id | 링크 고유 식별자 | uuid, PK |
| user_id | 소유자 | uuid → auth.users.id |
| url | 원본 링크 주소 | text |
| title | OG 제목(자동 수집, 수집 실패 시 수동 입력) | text |
| thumbnail_url | OG 썸네일 이미지 (description은 상세 표시용으로 함께 저장) | text, nullable |
| tags | 사용자 지정 태그 배열(분류 겸용) | text[] |
| memo | 저장 이유 메모 | text, nullable |
| is_read | 읽음 여부 | boolean, default false |
| is_favorite | 즐겨찾기 여부 | boolean, default false |
| created_at | 저장 일시(목록 정렬 기준) | timestamptz, default now() |

description은 별도 컬럼(text, nullable)으로 함께 저장하되 목록 카드에는 노출하지 않고 저장만 해둔다(향후 상세 뷰 확장 대비). 태그는 Postgres 배열 컬럼으로, 자동완성 없이 자유 텍스트 입력(쉼표 구분)으로 구현하며 태그 마스터 테이블은 만들지 않는다 — 당장은 자유 텍스트로 충분할 것으로 판단.

### profiles

| 필드명 | 설명 | 타입/관계 |
|---|---|---|
| id | 사용자 식별자 | uuid, PK → auth.users.id |
| display_name | 표시 이름 | text, nullable |
| avatar_url | 프로필 이미지 주소 | text, nullable |
| created_at | 생성 일시 | timestamptz, default now() |
| updated_at | 수정 일시 | timestamptz, default now() |

`auth.users`에 새 계정이 생성될 때 트리거로 자동 동기화되는 인프라 테이블이며, F001~F007 어느 기능에도 속하지 않는다. `[가정]` 참고.

## 7. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 프론트엔드 | Next.js 15 (App Router) + React 19 + TypeScript | 기존 프로젝트에 이미 세팅됨. Server Actions로 링크 저장/수정/삭제를 별도 API 레이어 없이 처리 가능해 1인 개발에 적합 |
| UI | shadcn/ui + Tailwind CSS 4 | 필요한 컴포넌트는 `npx shadcn add`로 추가 설치(`dialog`, `textarea`, `select`, `tabs` 등)하고, shadcn/ui가 제공하지 않는 요소는 직접 구현한다 |
| 백엔드/DB | Supabase (Postgres) | 기존 세팅 유지. `links` 테이블 1개만 추가하면 되므로 별도 백엔드 서버 불필요 |
| 인증 | Supabase Auth (`@supabase/ssr`) | 이미 구현 완료, 추가 개발 없음 |
| 메타데이터 수집 | `open-graph-scraper` 라이브러리를 Next.js Server Action/Route Handler에서 호출해 OG 태그 파싱 | 잘 알려진 오픈소스 라이브러리로, 직접 파싱 로직을 짤 필요 없이 단일 함수 호출로 처리. 수집 실패 시 제목 수동 입력으로 대체(수동 폴백) `[가정]` |
| 배포 | Vercel | Next.js와 통합이 가장 단순하고 무료 티어로 1인 프로젝트에 충분 |

## 8. 의도적으로 미루는 것

- **성능 최적화(페이지네이션, 무한스크롤)**: 초기 사용자의 링크 수가 적어 전체 목록 렌더링으로 충분.
- **RLS 정책 세분화, Rate limiting**: 기본 RLS(본인 데이터만 접근)만 적용하고 세밀한 권한 분리는 다중 사용자 확장 시점에 처리.
- **메타데이터 수집 실패 재시도/큐 처리**: 실패 시 즉시 수동 입력으로 대체하면 되므로 재시도 로직 불필요.
- **테스트 코드 커버리지**: 기능 자체가 아직 검증 전이라 테스트보다 동작 확인이 우선.
- **모바일 앱/PWA**: 반응형 웹으로 우선 대응, 네이티브 경험은 필요성이 확인된 후 검토.

## 9. 가정 및 확인 필요

- `[가정]` 메타데이터 수집은 직접 파싱 로직을 구현하는 대신 잘 알려진 오픈소스 라이브러리 `open-graph-scraper`를 사용하며(대안: `metascraper`, 더 모듈형이지만 MVP에는 과함), 실패 시 제목 수동 입력으로 대체한다.
- `[확인 필요]` 현재 프로젝트에는 Tailwind CSS 3.4.1이 설치되어 있어, 4로 업그레이드하는 작업이 별도로 필요함.
- `[확인 완료]` 메타데이터 수집: 로그인 필요 페이지 등 일부 사이트는 OG 태그 대신 일반적인(generic) 값을 반환하는 경우가 있었으나 오류로 이어지지 않았고, 수집 실패 케이스에서는 수동 입력 폴백이 정상 동작함을 프로덕션 실사용 검증(Task 16)으로 확인함. 별도 재시도/큐 처리 없이 현재 UX로 충분.
- `[가정]` `profiles` 테이블은 Supabase 공식 [managing-user-data](https://supabase.com/docs/guides/auth/managing-user-data) 가이드를 따른 인프라 확장이며 현재 어떤 기능(F001~F007)에도 매핑되지 않는다. `auth.users`를 클라이언트/조인에 직접 노출하지 않기 위한 것으로, 추후 표시 이름·아바타 설정 UI가 필요해질 때 스키마 재작업 없이 바로 쓸 수 있게 미리 마련해 둔다. 1인 개인용 서비스 특성상 공식 예시의 `anon` SELECT 권한은 부여하지 않고 본인 행만 조회·수정 가능하도록 RLS를 제한한다.
